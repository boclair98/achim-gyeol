# 아침결 운영 사고 대응

## 즉시 조치

1. `/studio` 운영 화면에서 **긴급 발행 중단**을 누르고 사고 내용과 이유를 기록합니다.
2. 발송 전이면 에디션과 모든 뉴스가 `HELD`로 바뀌며 추가 발송이 중단됩니다.
3. 이미 발송된 내용이면 영향을 받은 뉴스, 근거 출처, 발송 기기 수와 최초 인지 시각을 기록합니다.
4. 관리자 토큰·API 키·VAPID 키 노출이 의심되면 해당 키를 먼저 교체하고 이전 관리자 토큰은 복구가 끝난 뒤 제거합니다.

## 복구와 정정

1. 원문과 독립 출처를 다시 확인합니다.
2. 뉴스 검수 화면의 **정정 발행**으로 수정 전·후 내용과 이유를 남깁니다.
3. 보류된 뉴스 상태를 `APPROVED`로 변경한 후 에디션을 최종 승인합니다.
4. 실패한 발송만 재시도하며 이미 성공한 기기에는 중복 발송하지 않습니다.
5. 감사 로그에서 `EDITORIAL_INCIDENT_DECLARED`, `STORY_CORRECTED`, `EDITION_APPROVED` 순서를 확인합니다.

## 사후 점검

- 원인, 영향, 복구 시간, 재발 방지 조치를 GitHub 비공개 운영 기록 또는 접근이 제한된 문서에 남깁니다.
- 개인정보 유출 가능성이 있으면 추가 수집과 처리를 중단하고 관련 전문가에게 신고·통지 의무를 확인합니다.
- 다음 배포 전에 CI, 운영 모니터, 데이터 백업과 복구 절차를 다시 실행합니다.
